# MA — 강원도를 인터페이스로 번역한 웹 스터디

강원특별자치도 18개 시군을 산과 바다 두 장의 관광 이미지로 압축하지 않고,
공개 사진과 지형 자료에서 읽은 색·간격·경계·리듬을 반응형 웹의 규칙으로
번역한 자발적 디자인 케이스 스터디입니다.

> 서로 다른 조건을 가진 강원도의 18개 지역을 하나의 인터페이스 언어로 번역할 수 있을까?

## 범위

- 18개 시군에 대한 짧은 디자인 해석
- 출처와 라이선스를 개별 표기한 Wikimedia Commons 사진 9장
- HTML과 CSS로 그린 형태 연구 6개와 합성 장면 1개
- 겨울 안개, 얼음, 먹색, 이끼, 돌, 흙, 유리로 구성한 재료 7개
- 프레임워크 없이 작성한 HTML, CSS, JavaScript

지역을 묶는 방식과 `물 / 지형 / 경계 / 리듬 / 재료` 렌즈는 공인된 지리 분류가
아니라 이 프로젝트가 화면의 규칙을 찾기 위해 사용한 해석입니다.

## 페이지 구성

1. **Project brief** — 질문, 범위, 제약, 산출물, 자료
2. **Place** — 백두대간을 경계가 아닌 연결 구조로 다시 읽기
3. **Translation** — 안개·능선·이끼·서리·탄광 기억·동해안을 UI 규칙으로 변환
4. **Evidence chain** — 근거 → 해석 → 결정 → 실제 구현
5. **Translation lab** — 투명도, 간격, 1px 선, 강조색 빈도를 직접 조절
6. **Drawings** — CSS만으로 만든 여섯 형태 연구와 한 개의 합성 장면
7. **Regions** — 18개 지역을 프로젝트의 디자인 렌즈로 탐색
8. **Materials / Concept** — 일곱 재료와 세 개의 설계 원칙
9. **Alternatives / Critique** — 비교한 방향, 가장 잘된 선택, 한계, 다음 질문
10. **Authorship** — 제작 범위, 공개 사진, 생성형 AI 사용 범위 공개

## 디자인 시스템

```css
:root {
  --paper: #EEF1F2;      /* 겨울 안개 */
  --paper-deep: #DBE2E4; /* 성엣장 */
  --ink: #1C2325;        /* 탄광 기억을 번역한 먹색 */
  --accent: #4B6560;     /* 이끼 — 유일한 유채색 */
  --stone: #8A9296;      /* 돌 */
  --soil: #5D6A6D;       /* 겨울 흙 */
}
```

헤더는 안개가 뒤의 정보를 지우지 않고 선명도만 낮추는 성질을 반투명 표면과
`backdrop-filter`로 구현합니다. 이를 지원하지 않거나 투명도 축소를 선호하는
환경에서는 불투명한 배경으로 대체됩니다.

## 인터랙션과 접근성

- 시스템 글꼴(`-apple-system` / SF 계열 우선)만 사용해 외부 폰트 요청 없이 운영체제의 한글 글꼴로 자연스럽게 대체
- `Translation`의 긴 호흡을 CSS `position: sticky`와 작은 시선 이동으로 구성하고, `requestAnimationFrame`을 `IntersectionObserver`로 화면 안에서만 갱신
- 스크롤 중인 장을 공통 내비게이션의 `aria-current`로 표시하고, 헤더는 내용이 겹칠 때만 반투명 스크롤 엣지를 표시
- 재료 견본의 포인터 드래그, 속도 인계, 스프링 스냅과 키보드 방향키 이동
- 네 개의 네이티브 range control을 사용하는 Translation Lab과 초기화 버튼
- `aria-pressed` 버튼과 `aria-live` 결과를 사용하는 지역 디자인 렌즈 필터
- 모바일에서도 사라지지 않는 가로 스크롤 섹션 내비게이션
- 본문 바로가기, 명확한 포커스 표시, 의미 있는 제목 구조와 이미지 대체 텍스트
- 라이트·다크 모드, 고대비, 모션 축소, 투명도 축소, 인쇄 스타일 대응
- JavaScript가 꺼져도 모든 본문과 지역 정보가 보이는 점진적 향상 구조

사진은 원본 JPEG를 폴백으로 남기고, 640·960·1200px WebP 파생본을 `<picture>`,
`srcset`, `sizes`로 선택합니다. 모든 본문 이미지는 고유 크기를 유지한 채 지연 로드되어
레이아웃 이동과 불필요한 전송량을 줄입니다.

## 실행

빌드 과정과 패키지 설치가 필요 없습니다.

```text
index.html을 브라우저에서 열기
```

ES module을 로컬 파일 정책 때문에 불러오지 못하는 브라우저에서는 프로젝트 루트에서
간단한 정적 서버를 실행합니다.

```bash
python3 -m http.server 8000
```

## 자료와 저작권

사진 9장의 저작자, 라이선스, 원문 링크는 페이지의 각 캡션과
[`CREDITS.md`](./CREDITS.md)에 기록했습니다. 지역별 문장은 공개 자료를 바탕으로 한
프로젝트의 편집적 해석이며, 여행·행정·지리 안내 자료로 사용하기 위한 것이 아닙니다.

지역 지리 표현 일부를 검토할 때 강원특별자치도의 [행정구역](https://state.gwd.go.kr/portal/introduce/situation/district)과
[위치·지세](https://state.gwd.go.kr/portal/introduce/situation/position),
[태백시 발원지 안내](https://tour.taebaek.go.kr/tour/),
[철원군 지형](https://www.cwg.go.kr/www/contents.do?key=232) 등 공식 자료를 참고했습니다.
페이지의 디자인 렌즈와 화면 번역은 공인 분류가 아니라 제작자의 편집 판단입니다.

## 제작 및 생성형 AI 사용

- 프로젝트 주제, 요구사항, 최종 승인: **정찬용**
- 구조·문장·코드: 생성형 AI 보조를 받아 제작
- 최종 판단과 승인: 제작자

생성형 AI를 사용하지 않은 단독 제작물로 주장하지 않습니다. 사진 역시 제작자가 직접
촬영한 것으로 주장하지 않으며, 모든 공개 이미지의 출처를 개별 표기합니다.

## 회원가입 · 로그인 (Supabase Auth)

헤더의 회원가입 버튼에서 이메일 회원가입, 로그인, 현재 기기 로그아웃,
비밀번호 재설정을 이용합니다. 기존 본문은 로그인 없이 그대로 볼 수 있습니다.
브라우저 인증 SDK는 `@supabase/supabase-js@2.116.0`으로 고정했습니다.
`js/auth.js`에는 공개용 publishable key만 포함하며 관리자 키는 사용하지 않습니다.
사용자는 Supabase Auth에 저장되고 별도 공개 회원 테이블은 만들지 않습니다.

### 배포 전 인증 설정

Supabase 프로젝트 `vwvkonfvwdkdvnjedbnx`의 Authentication 설정에서 다음을 확인합니다.

1. URL Configuration의 Site URL을 실제 운영 주소로 설정합니다.
2. Redirect URLs에 운영 주소의 `/`와 `/index.html`,
   `https://jcy0908.github.io/ma-admissions/`,
   `https://jcy0908.github.io/ma-admissions/index.html`을 등록합니다.
3. 이메일 확인을 사용할 경우, 일반 방문자에게 발송 가능한 Custom SMTP를 연결합니다.
   Supabase 기본 메일 서버는 프로젝트 팀원 주소에만 발송하며 제한이 있으므로
   공개 회원가입용 메일 서버로 사용할 수 없습니다.
4. 실제 메일함으로 가입 → 인증 → 로그인 → 새로고침 → 로그아웃과
   비밀번호 재설정 링크 → 새 비밀번호 로그인 과정을 확인합니다.

참고: https://supabase.com/docs/guides/auth/auth-smtp

### Vercel

프레임워크는 Other, 빌드 명령과 설치 명령은 비워 둡니다.
`vercel.json`은 정적 배포를 지원하고, 이미지가 배포에 포함되지 않은 경우
기존 GitHub Pages의 `/img/` 자료를 가져오는 rewrite를 제공합니다.
GitHub Pages에서도 동일한 HTML/CSS/JavaScript가 동작합니다.

## Google 로그인과 색상 테마

- 하단의 포인트 색상에서 기본·초록·파랑·황토를 선택할 수 있습니다. 배경과 본문은 무채색을 유지합니다.
- 선택값은 브라우저에 저장되며 시스템 다크 모드도 지원합니다.
- Google 버튼은 Supabase의 Google provider 활성화 여부를 확인한 다음 OAuth로 연결합니다.
- Google Cloud의 웹 애플리케이션 OAuth 클라이언트를 만들고 Supabase Google provider에
  Client ID와 Client Secret을 설정해야 실제 로그인이 가능합니다. Secret은 브라우저 코드에 넣지 않습니다.
- Google의 Authorized redirect URI는 `https://vwvkonfvwdkdvnjedbnx.supabase.co/auth/v1/callback`입니다.
- 사이트 URL은 기존 인증 설정의 Redirect URLs에도 허용해야 합니다.
- 현재 실제 Google 계정 로그인은 관리자 설정 완료 후 검증해야 합니다.
- 설정 참고: https://supabase.com/docs/guides/auth/social-login/auth-google

## 여행 계획과 통합 화면

- 지역 / 여행 계획 / 보관함의 세 화면, 무채색 바탕과 선택·저장·안내에만 쓰는 포인트 색상
- 18개 시·군의 이름은 기본 목록에 모두 표시하고 상세 설명은 개별 펼침으로 제공
- 지역 검색과 즐겨찾기 중복 제거, 기존 사진·이야기·실험은 풍경과 제작 기록에 통합
- 추가 조건·캘린더·파일·순서 변경은 필요한 위치에서 펼침
- 기존 18개 지역 기록·즐겨찾기·번역 실험 유지
- 춘천·강릉·속초·원주·철원·영월 중 취향별 추천 및 직접 선택
- 1~7일 일정, 인원·전체 예산·여행 강도·이동수단·필수 장소 반영
- 추천 장소는 반복하지 않으며 후보가 부족하면 자유시간 제공
- 장소·체류시간·비용·메모 편집, 날짜 이동, 순서 변경, 삭제와 되돌리기
- 예상 경비 합계·1인 경비·예산 초과 안내, 숙박·교통비 직접 수정
- 기존 개인 저장 서비스와 연동: 방문자 기기 저장, 회원 계정 저장
- 파일 가져오기·내보내기, 개인 메모를 뺀 공유 링크, 캘린더와 인쇄
- 실제 교통 경로·운영시간·실시간 가격·AI 모델을 호출하지 않습니다.
  일정은 공개 관광 자료를 토대로 만든 편집 가능한 초안이고 비용은 계획용 추정치입니다.

`js/journey-core.mjs`는 일정 생성·검증·경비·캘린더, `js/journey.js`는 편집 화면,
`css/journey.css`는 계획 화면, `css/palette.css`는 색상 토큰을 담당합니다.
`js/workspace.js`와 `css/workspace.css`는 화면 이동과 통합 배치를 담당합니다.
여행 기록은 기존 `bootcamp_user_data`의 `workspace.value.journey`에 저장하며
기존 RLS와 revision 조건부 저장을 사용합니다. 새 테이블·권한 변경은 없습니다.

검증: 날짜 역전·윤년·7일 제한, 추천 중복 방지, 필수 장소·도보 조건,
비용 합계, 변경 후 시간 계산, 잘못된 가져오기 형식 차단, 캘린더 UTC 변환.
실제 계정 로그인은 기존 Supabase 공급자 및 이메일 설정 상태에 따릅니다.

화면 동작 검증: 실제 HTML을 DOM 파서로 불러와 일정 생성, 날짜 전환 컨트롤,
저장, 삭제·되돌리기, 공유 링크, 삽입된 HTML의 이스케이프, 계정 전환 시 입력 초기화를 확인했습니다.
실제 브라우저의 시각 검수 및 이메일·Google 인증 완료 테스트는 수행하지 않았습니다.

구성 변경 검증: 18개 이름·설명과 기존 사진의 보존, 화면 이동·뒤로 가기·직접 링크,
방문자 즐겨찾기 저장·해제와 지역 검색 복원을 DOM 파서로 확인했습니다.
